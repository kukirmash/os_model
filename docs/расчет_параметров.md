# Расчёт параметров модели ОС (лабораторная работа 7)

Документ описывает расчёт времени выполнения заданий в однопрограммном и
мультипрограммном режимах, а также показатели эффективности мультипрограммирования.

**Где реализовано:**

| Файл | Назначение |
|---|---|
| `internal/process/psw.go` | составляющие системных затрат в слове состояния процесса |
| `internal/regulator/costs.go` | длительности системных действий и значения по умолчанию |
| `internal/regulator/regulator.go` | подпрограмма `IncreaseReadyTime`, начисление затрат при событиях |
| `internal/stats/times.go` | `T_mono`, `T_multi`, `D_exe`, `D_ready` |
| `internal/stats/stats.go` | накопители `ΣT_mono`, `ΣT_multi`, `T_сист`, `M_mono`, `D_multi`, `D_sys` |
| `internal/os/system.go` | конфигурация затрат, `LoadTask`, отключение автозагрузки в тестах |
| `internal/os/snapshot.go` | данные для интерфейса (типы с префиксом `UI`) |
| `frontend/dist` | панели сравнения режимов и параметров процессов |

## Обозначения

| Обозначение | Смысл |
|---|---|
| `T_мод` (`Time`) | модельные такты выполнения пользовательских команд и ВВ |
| `T_сист` (`SystemTicks`) | суммарное время системных действий, тактов |
| `T_эфф` | `T_мод + T_сист` — время работы модели с учётом системных затрат |
| `T_загр` | время загрузки задания (`LoadTicks`) |
| `T_ЦПр` | время выполнения на центральном процессоре (`ExecTicks`) |
| `T_ВВ` | время инициализации и блокировки ВВ (`IOTicks`) |
| `T_заверш` | время завершения задания (`TermTicks`) |
| `T_перекл` | время переключений «Готов» → «Активен» (`SwitchTicks`) |
| `T_иниц.ВВ` | логическая инициализация ВВ (`IOInitTicks`) |
| `T_прерыв` | обслуживание прерываний ВВ (`IOIntrTicks`) |
| `T_ожид` | ожидание в очереди готовности (`WaitTicks + SystemWaitTicks`) |
| `T_блок.пам` | блокировка по памяти — в модели не возникает, равна 0 |

## 1. Время процесса в однопрограммной ОС

В однопрограммном режиме задание выполняется без конкуренции за процессор:

```text
T_mono(p) = T_загр + T_ЦПр + T_ВВ + T_заверш
```

Поля `LoadTicks`, `TermTicks` начисляются при загрузке и завершении,
`ExecTicks` и `IOTicks` — каждый такт по текущему состоянию процесса
(лабораторная работа 6).

## 2. Время процесса в мультипрограммной системе

К `T_mono` добавляются затраты, которых нет в однопрограммном режиме:

```text
T_multi(p) = T_mono(p)
           + T_перекл
           + T_иниц.ВВ
           + T_прерыв
           + T_ожид
```

Переключение «Активен» → «Готов» в варианте 11 не моделируется (нет
вытеснения по таймеру), блокировка по памяти отсутствует, поэтому эти
составляющие равны нулю.

Производные показатели процесса:

```text
D_exe(p)   = T_multi(p) / T_mono(p) · 100 %
D_ready(p) = T_ожид(p) / T_multi(p) · 100 %
```

## 3. Системные действия и подпрограмма IncreaseReadyTime

Системные действия и их длительности:

| Действие | Поле `Costs` | Диапазон по умолчанию |
|---|---|---:|
| Загрузка задания | `Load` | 1 |
| Выбор и активация процесса | `Dispatch` | 1 |
| Логическая инициализация ВВ | `IOInit` | 1 |
| Обслуживание прерывания ВВ | `IOInterrupt` | 1 |
| Завершение задания | `Terminate` | 1 |

Диапазоны задаются в `params.json` (лабораторная работа 8) и один раз
генерятся при запуске. Если файл не найден, используются значения по
умолчанию из `params.Default()`.

Подпрограмма `Regulator.IncreaseReadyTime(ticks)`:

```text
для каждого процесса p в таблице PSW:
    если p.State == «Готов»:
        p.SystemWaitTicks += ticks
```

Вызывается при загрузке, активации, запросе ВВ, завершении ВВ и завершении
процесса. Собственные затраты процесса начисляются в его поля
(`LoadTicks`, `SwitchTicks`, `IOInitTicks`, `IOIntrTicks`, `TermTicks`),
а глобальные — в `Stats.SystemTicks` один раз на действие.

## 4. Показатели системы

```text
T_эфф   = T_мод + T_сист
M_multi = CompletedCount
T_mono_avg = ΣT_mono(p) / M_multi
M_mono  = T_эфф / T_mono_avg
D_multi = M_multi / M_mono · 100 % = ΣT_mono(p) / T_эфф · 100 %
D_sys   = T_сист / T_эфф · 100 %
```

`D_multi > 100 %` означает, что за время работы модели в мультипрограммном
режиме выполнено больше заданий, чем могло бы выполниться в однопрограммном
за то же эффективное время.

## 5. Граничные случаи

- При `M_multi = 0` средние и `M_mono` равны 0, деление не выполняется.
- При `T_mono = 0` показатель `D_exe` принимается равным 0.
- При `T_multi = 0` показатель `D_ready` принимается равным 0.
- При `T_эфф = 0` показатели `D_multi` и `D_sys` равны 0.
- `T_mono <= T_multi <= T_эфф` для каждого процесса — проверяется тестами.
