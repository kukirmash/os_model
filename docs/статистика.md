# Статистика модели ОС (лабораторная работа 6)

Документ описывает параметры статистики, которые вычисляются в модели ПО «Модель ОС»
для анализа эффективности метода распределения времени центрального процессора
(вариант 11 — относительные и динамические приоритеты), и формулы их расчёта.

**Где реализовано:**

| Файл | Назначение |
|---|---|
| `internal/process/psw.go` | счётчики времени в слове состояния процесса |
| `internal/stats/stats.go` | накопители, сбор статистики за такт, средние значения |
| `internal/regulator/regulator.go` | регистрация загрузки и завершения процесса |
| `internal/os/system.go` | шаг «Сб» такта, выбор процесса на ЦПр, параметры нового задания |
| `internal/os/snapshot.go` | передача статистики в интерфейс (`Snapshot`) |
| `internal/os/system_test.go` | проверка согласованности статистики |

## Обозначения

| Обозначение | Смысл |
|---|---|
| `T` (`Now`) | текущий такт модели (модельное время), тактов |
| `N` (`LoadedCount`) | всего загружено заданий за прогон |
| `M` (`CompletedCount`) | всего завершено процессов за прогон |
| `L(t)` | длина очереди готовности в такт `t` |
| `K(t)` | число занятых процессоров ВВ в такт `t` |
| `t_загр` | такт загрузки процесса (`LoadedAt`) |
| `t_заверш` | такт завершения процесса |

Все времена измеряются в тактах моделирования.

## 1. Времена процесса (слово состояния PSW)

Для каждого процесса в `PSW` ведутся счётчики, которые увеличиваются на 1 каждый такт,
пока процесс находится в соответствующем состоянии (шаг «Сб» такта):

| Параметр | Поле | Что учитывает |
|---|---|---|
| Время ожидания | `WaitTicks` | такты в состоянии «Готов» (в очереди готовности) |
| Время выполнения | `ExecTicks` | такты в состоянии «Активен» (работа на ЦПр) |
| Время ввода-вывода | `IOTicks` | такты в состояниях «Инициализация IO» и «Блокирован» |
| Такт загрузки | `LoadedAt` | такт, в котором задание было загружено в память |

Оборотное время процесса (время от загрузки до текущего момента, для завершённого —
до завершения):

```text
Turnaround = T − t_загр
```

Каждый такт процесс находится ровно в одном из состояний, поэтому выполняется
тождество (проверяется тестом):

```text
WaitTicks + ExecTicks + IOTicks = T − LoadedAt
```

Загрузочный такт в счётчики не входит: статистика фиксируется в начале такта,
после диспетчеризации и до выполнения команды.

## 2. Показатели системы (накопители)

`Stats` накапливает значения за весь прогон:

| Параметр | Поле | Формула / правило |
|---|---|---|
| Занятые такты ЦПр | `CPUBusy` | `+1`, если в такте есть активный процесс и ЦПр выполняет команду |
| Простой ЦПр | `CPUIdle` | `+1`, если ЦПр ожидает |
| Сумма длин очереди готовности | `ReadySum` | `Σ L(t)` по всем тактам |
| Максимальная длина очереди | `ReadyMax` | `max L(t)` по всем тактам |
| Сумма занятых процессоров ВВ | `IOBusySum` | `Σ K(t)` по всем тактам |
| Максимум занятых процессоров ВВ | `IOBusyMax` | `max K(t)` по всем тактам |
| Последовательность выполнения | `ExecHistory` | до 16 последних номеров процессов, выбранных планировщиком на ЦПр |
| Загружено заданий | `LoadedCount` | `+1` при каждой успешной загрузке |
| Завершено процессов | `CompletedCount` | `+1` при каждой выгрузке процесса |

Накопители входных параметров загруженных заданий:

| Параметр | Поле |
|---|---|
| Сумма размеров заданий | `SumSize` |
| Сумма числа команд | `SumCommands` |
| Сумма процентов команд ВВ | `SumIOPercent` |
| Сумма базовых приоритетов | `SumBasePriority` |

Накопители выходных параметров завершённых процессов:

| Параметр | Поле | Что суммируется |
|---|---|---|
| Сумма времён ожидания | `SumWait` | `Σ WaitTicks` завершённых процессов |
| Сумма времён выполнения | `SumExec` | `Σ ExecTicks` |
| Сумма времён ввода-вывода | `SumIO` | `Σ IOTicks` |
| Сумма оборотных времён | `SumTurnaround` | `Σ (t_заверш − t_загр)` |

## 3. Производные показатели эффективности

### 3.1. Загрузка центрального процессора

Полезная загрузка — доля тактов, в которых ЦПр выполнял команды:

```text
CPUUtilization = CPUBusy / T × 100 %
```

Дополнительно выполняется `CPUBusy + CPUIdle = T`.

### 3.2. Производительность системы

Число завершённых заданий в расчёте на 1000 тактов модельного времени:

```text
Throughput = CompletedCount × 1000 / T   (заданий на 1000 тактов)
```

В заданиях на один такт: `CompletedCount / T`.

### 3.3. Длины очередей

```text
ReadyAvg = ReadySum / T        — средняя длина очереди готовности
ReadyMax                       — максимальная длина очереди
IOBusyAvg = IOBusySum / T      — среднее число занятых процессоров ВВ
IOBusyMax                      — максимум одновременно занятых процессоров ВВ
```

Текущие значения (`ReadyLen`, `IOBusy`) берутся из ядра в момент формирования снимка.
Очереди к процессорам ВВ не моделируются (процессоров достаточно), поэтому для ВВ
показывается именно число занятых процессоров.

## 4. Средние значения параметров процессов

### 4.1. Входные параметры — по всем загруженным заданиям (N)

```text
AvgSize      = SumSize / N          — средний размер задания, единиц памяти
AvgCommands  = SumCommands / N      — среднее число команд
AvgIOPercent = SumIOPercent / N     — средний процент команд ВВ, %
AvgPriority  = SumBasePriority / N  — средний базовый приоритет
```

### 4.2. Выходные параметры — по завершённым процессам (M)

```text
AvgWait       = SumWait / M               — среднее время ожидания, тактов
AvgExec       = SumExec / M               — среднее время выполнения на ЦПр, тактов
AvgIO         = SumIO / M                 — среднее время ввода-вывода, тактов
AvgTurnaround = SumTurnaround / M         — среднее оборотное время, тактов
```

Средние выходные параметры накапливаются в момент выгрузки процесса, поэтому они
не «теряются» после удаления записи из таблицы PSW.

## 5. Последовательность выполнения процессов на процессоре

При каждом выборе процесса планировщиком (`dispatchProcess`) его номер добавляется
в конец списка `ExecHistory`. Хранятся последние 16 номеров:

```text
если len(ExecHistory) > 16: удалить первый элемент
```

Повторяющийся номер означает, что процесс вернулся на ЦПр после завершения
операции ввода-вывода или ожидания в очереди готовности.

## 6. Отображение в интерфейсе

| Раздел интерфейса | Что показывает |
|---|---|
| «Параметры системы» | загружено/выполнено, длины очередей (текущая/средняя/макс.), процессоры ВВ (текущее/среднее/макс.), производительность, память |
| «Параметры центрального процессора» | занятые/простаивающие такты, полезная загрузка |
| «Параметры нового задания» | параметры последнего задания и причина отказа при загрузке |
| «Параметры процессов (таблица PSW)» | ожидание, выполнение, ВВ и оборотное время каждого процесса |
| «Последовательность выполнения процессов на процессоре» | последние 16 номеров |
| «Средние значения параметров процессов» | средние входные (N) и выходные (M) параметры |

В снимке состояния (`Snapshot`) эти данные передаются в поля:

- `ProcessInfo`: `waitTicks`, `execTicks`, `ioTicks`, `turnaround`;
- `StatsInfo`: `cpuBusy`, `cpuIdle`, `cpuUtilization`, `readyLen`, `readyAvg`,
  `readyMax`, `ioBusy`, `ioBusyAvg`, `ioBusyMax`, `throughput`, `execHistory`,
  `loadedCount`, `avgSize`, `avgCommands`, `avgIoPercent`, `avgPriority`,
  `completedCount`, `avgWait`, `avgExec`, `avgIo`, `avgTurnaround`;
- `LastTask`: параметры нового задания (`size`, `totalCommands`, `ioPercent`,
  `basePriority`, `loaded`, `reason`).

## 7. Граничные случаи

- При `T = 0`, `N = 0` или `M = 0` соответствующие средние и производные показатели
  принимаются равными `0` (деление на ноль не выполняется).
- Средние входные параметры считаются по всем загруженным заданиям, включая ещё
  не завершённые; средние выходные — только по завершённым процессам.
- Оборотное время резидентного процесса в таблице PSW отображается как
  `T − LoadedAt` и растёт каждый такт; в среднее оборотное время попадает
  значение на момент завершения.

## 8. Проверка корректности

`internal/os/system_test.go` прогоняет модель на несколько тысяч тактов и проверяет:

- `CPUBusy + CPUIdle = T`;
- `WaitTicks + ExecTicks + IOTicks = T − LoadedAt` для каждого процесса;
- `Σ ExecTicks` (резидентные + завершённые) `= CPUBusy`;
- `LoadedCount =` число загруженных заданий ядра;
- `CompletedCount =` число завершённых заданий ядра;
- длина `ExecHistory` не превышает 16;
- средние значения определены и не противоречат максимумам.

| Процессоры ВВ | занято 1, в среднем 1,5, максимум 5 |
| Средний размер задания (N = 16) | 319,9 ед. |
| Среднее число команд | 15,7 |
| Средний процент команд ВВ | 27,9 % |
| Средний базовый приоритет | 5,9 |
| Среднее время ожидания (M = 3) | 30,7 такта |
| Среднее время выполнения | 15,0 тактов |
| Среднее время ВВ | 6,0 тактов |
| Среднее оборотное время | 51,7 такта |

Значения соответствуют снимку, приведённому в отчёте по лабораторной работе 6

длительность ВВ, скорость) показатели пересчитываются автоматически.
